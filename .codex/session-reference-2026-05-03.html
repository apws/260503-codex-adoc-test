Page Break Investigation

The user saw unwanted breaks in the PDF. Source scan found chapter files with leading explicit page breaks:

<<<

== Chapter heading

Those were briefly removed from all chapter files, while preserving the <<< inside the chapter 01 syntax example.

PDF inspection then showed that the real heading-only pages were caused by print CSS, not only source page-break markers.

Relevant CSS rules:

css/mixworx-adoc-demo.css:
h2 {
  break-before: page;
  page-break-before: always;
}

css/mixworx-golo.css:
h2, h3 { page-break-before: always; }

Fix applied in additive CSS:

@media print {
  h2, h3 {
    break-before: auto;
    page-break-before: auto;
  }
}

The stale chapter 01 note was updated to say print mode keeps headings attached to content.
